## Why every submission overrides `eval_config.yaml`
The starter ships `max_time_minutes: 1`, `max_tool_calls: 10`, `max_turns: 50`. The official
harness applies these per task, far below anything we evaluate locally (6 min, no tool-call cap).
We use 5 min per task: 120 hidden tasks × 5 min = 10 h, inside the 12 h run limit.

## Calibration
The public score of #1 against our local starter-fixed rate is the first check that local
results transfer to the 4×L4 box. Record the score here as soon as it is known.

### 2026-09-27: #1 scored 0.03 against a local 31%. Local results do not transfer yet.
Facts from the competition page and host answers in the forum (read 2026-09-27):
- Public LB = 58 tasks (scores are floor(100·k/58)/100; 0.03 = 2 solved); ~120 tasks in total,
  split evenly public/private. Tasks run **sequentially** in one job with a **12 h limit**
  (sandbox setup counts, patch validation does not). Hitting the limit currently errors; the host
  plans to score unfinished tasks as 0. So the real per-task budget is ~6 min on 4×L4.
- The scorer reads only `timeout_seconds`, `max_tool_calls`, `max_time_minutes`, `max_turns`
  (default: no limit).
- The scorer runs a patched **vLLM 0.19.1**, where **LoRA adapters are silently wiped** (forum
  743508; host acknowledged). Any adapter submission scores as the base model. We run vLLM 0.30
  locally, so all our local runs so far include a LoRA effect Kaggle does not have.
- Community reference points: best public notebook 0.12 (the starter plus max_output_tokens 8192,
  temperature 0.2, top_k 40, **no adapters**); a fork of it scored 0.08 and took 14.5 h of wall
  time; a bare-bones submission scored 0.08; the starter-kit notebook 0.05; the official sample
  (with adapters) FAILED.

Candidate causes of the gap, to test locally before the next submission:
1. **Speed.** 4×L4 decodes slower than one 5090 (local: ~55 tok/s single stream), so 5 min on L4
   buys far fewer steps. Locally we also ran 2 tasks at once, while Kaggle runs one.
2. **`timeout_seconds: 300` = the whole 5 min budget.** One hanging test command (e.g. the rich
   test suites that loop) ends the task. The starter uses 60.
3. **LoRA fidelity.** Local runs apply the starter LoRA; Kaggle does not.
4. **Noise.** At ~10% solve rate, the SD over 58 tasks is ~2.3 tasks (0.04), so 0.03 vs 0.08 is
   ~2 SD.
5. **Thinking is unbounded on the scorer (found 2026-09-27 in the official wheels).**
   adk_submission 0.2.11 never sends `thinking_budget` to vLLM, so thinking runs up to
   `max_output_tokens` per step (8192 in lb01), while our local runs capped it at 4096. See
   `docs/design_changes.md`. Ladder step 3 measures it.
